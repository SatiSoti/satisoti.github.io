# ゲーム本体を担当する AI へ

対象：コミック発展国 キャラクター素材セット `1.0.0`  
更新日：2026-10-12（日本時間）

このセットは、別の AI が開発中のコミック発展国とファイルの編集が競合しないよう、独立したキャラクター制作プロジェクトで作成しました。制作側はゲーム本体のリポジトリを編集していません。ここにあるのは受け渡し用の素材と描画モジュールです。

## 担当範囲

| 担当 | 所有する作業 |
| --- | --- |
| キャラクター制作側 | 固定デザイン、画像、プロフィール、素材の切り出し・動作定義、配布版の作成 |
| ゲーム本体側 | 読み込み用アダプター、人物データとの対応、能力・採用・登場条件、移動・配置・セーブとの接続 |

キャラクター制作側の試作サイト一式を、本体の代わりとしてコピーしないでください。本体には、この配布フォルダーと必要なアダプターだけを取り込みます。制作側からの自動同期や自動マージはありません。

## 取り込む前に

1. 本体リポジトリの現在の `AGENTS.md` などの作業指示と `git status` を確認します。他の AI の作業中ファイル・未コミット変更を保護し、並行作業中なら専用ブランチまたは worktree を使います。
2. ZIP を別の一時フォルダーに展開し、`README.md`、`manifest.json`、`manifest.schema.json`、`CHANGELOG.md` を読みます。
3. `checksums.json` の SHA-256 と展開後のファイルを照合します。チェックサムはこの配布物内の同一性の確認用で、公開署名ではありません。違いがあれば、意図した変更か破損かを確認してから使用します。
4. 本体の既存キャラ形式、素材配置、描画の座標系、セーブ内の ID を確認し、最小限の接続方法を選びます。

`checksums.json` は `{ "algorithm": "sha256", "files": { "相対パス": "ハッシュ値" } }` の形式です。自己参照を避けるため `checksums.json` 自体は対象外です。Python がある環境なら、展開先で次の照合を行えます。

```sh
python3 - <<'PY'
import hashlib
import json
from pathlib import Path

base = Path('.')
checksums = json.loads((base / 'checksums.json').read_text())
assert checksums['algorithm'] == 'sha256'
for name, expected in checksums['files'].items():
    actual = hashlib.sha256((base / name).read_bytes()).hexdigest()
    if actual != expected:
        raise SystemExit(f'チェックサム不一致: {name}')
print(f"照合完了: {len(checksums['files'])} ファイル")
PY
```

## 推奨する取り込み方法

### 1. 配布物を新しい場所に置く

本体の構成に合わせ、未使用の専用名前空間にフォルダー全体をコピーします。例えば次の場所です。

```text
assets/characters/comic-hatten-specialists/v1.0.0/
```

これは配置例です。本体が `public/` や別の静的配信ディレクトリを使っていれば、それに合わせてください。`manifest.json`、`renderer.mjs`、`assets/` の相対関係は維持します。既存の画像、キャラデータ、ゲームコードを一括上書きするスクリプトは使いません。

### 2. 本体側にアダプターを作る

本体が Canvas 2D を使う場合、配布された `renderer.mjs` を読み込んで描画できます。ES Modules を直接使わない既存構成なら、本体の設計に沿った薄いアダプターを作ります。別の描画エンジンの場合は、`manifest.json` の情報で画像を切り出します。

```js
import { loadCharacterPack } from
  './assets/characters/comic-hatten-specialists/v1.0.0/renderer.mjs';

const pack = await loadCharacterPack(new URL(
  './assets/characters/comic-hatten-specialists/v1.0.0/manifest.json',
  import.meta.url
));

// x と y は足元の位置、time は秒。
pack.draw(ctx, {
  id: 'sumitani', action: 'work', time: animationSeconds,
  x: actor.x, y: actor.feetY, scale: 1, flip: false, shadow: true
});
```

この例のパスはアダプターファイルからの相対パスです。実際の配置に合わせて修正してください。`ctx.imageSmoothingEnabled = false` と、必要に応じて Canvas の CSS に `image-rendering: pixelated` を設定します。

動作キーは `idle`、`walk`、`work`、`cheer` の４つです。本体の状態名が異なれば、アダプターで対応付けます。既存の移動処理、仕事の進捗、休憩処理などは維持し、その状態に応じて絵を切り替えてください。描画モジュール自体は人物を移動させず、仕事の成果も計算しません。

### 3. 固定 ID で本体の人物に結び付ける

| ID | 名前 | `role` |
| --- | --- | --- |
| `sumitani` | 墨谷 玄舟 | `artist` |
| `hanamori` | 花守 リリカ | `artist` |
| `hoshino` | 星乃 トオル | `artist` |
| `takamine` | 鷹峰 律子 | `editor` |
| `nukui` | 温井 誠 | `editor` |
| `kazama` | 風間 晴 | `editor` |

本体で既に別の人物 ID 体系を使っている場合は、その ID と素材 ID の対応を保存します。名前や表示順をキーにしません。名前を変更しても同一人物として扱います。

凄腕キャラは顔・髪・服・持ち物が固定です。通常キャラ向けのランダム生成・着色・パーツ交換は、この６人に適用しないでください。固定とはプレイ中の見た目が勝手に変わらないという意味で、制作時の更新まで禁止する意味ではありません。

### 4. ゲームの数値は本体のルールで設定する

`gameplay` 内の `stats`、`unlockConditions`、`recruitmentCost` の `null` は未設定です。０や無料として計算しないでください。キャラの肩書き・性格・得意分野はデザイン設定であり、画力や構成力などの点数、採用費、登場年を確定していません。

`production.status: "ready"` は素材の準備完了です。本体との接続状態は `gameplay.implementationStatus: "not_integrated"` で、別の状態として扱います。

本体の現在の数値体系に沿って、能力や登場条件を本体側の人物定義に持たせてください。今回の取り込みだけを理由に、売上、初期資金、連載数、作品の成長曲線など既存のゲームバランスを変更しないでください。

## 素材の実装上の限界

- ６枚のシートに各８コマ、合計 48 コマあります。透過画像と矩形・足元情報がセットです。
- 斜め正面と左右反転で表示します。４方向・背面用の絵は含みません。
- 歩行４コマは試作用の動きです。すべてのコマで脚の左右が厳密に交互になる原画としては調整の余地があります。
- 机、椅子、部屋、当たり判定、経路探索、ゲーム UI は含みません。
- この版の受け渡し時点ではゲーム本体への接続は未実施です。素材が用意できたことと、本体への実装完了を区別して報告してください。

## 取り込み後の確認

本体の既存の確認方法に沿って、少なくとも次を確認します。

- ６人それぞれの画像が読み込め、待機・歩行・仕事・喜びが正しく切り替わる。
- 足元の位置、机の前後関係、左右反転、画面拡大時の見え方が自然である。
- 通常キャラの見た目変更が固定キャラに波及せず、別の人物の動きや設定も変わらない。
- 既存のセーブを読み込め、新規キャラの対応 ID を保存・復元できる。未設定値を０として扱っていない。
- 配信時の相対パスが正しく、外部 CDN や外部 API なしで JSON と PNG を取得できる。
- アニメーションを止められ、動きを減らす設定と既存ゲームの一時停止に従う。人物の名前・選択状態は絵だけに頼らず確認できる。

確認結果と、本体で追加したファイル・変更した接続箇所をまとめてから、ゲーム本体側の通常の反映手順で進めます。

## 次の版の受け渡し

新しい素材は `v1.1.0/` など別フォルダーで受け取り、`CHANGELOG.md` と固定 ID を比較します。アダプターの参照先を切り替えて確認し、問題がないと分かるまで旧版を残してください。

元の配布版に調整を加える必要がある場合は、調整内容を記録します。共通のデザイン変更は制作側へ伝えて次の配布版に取り込み、本体固有の位置合わせや能力値は本体側のアダプター・人物設定に保ちます。これにより、次回の素材更新で本体固有の調整が消えることを避けられます。

別の AI に渡すときは ZIP を添付し、この文書を最初に読ませてください。試作サイトの URL はログインが必要な場合があり、URL だけでは素材を取得できないことがあります。
